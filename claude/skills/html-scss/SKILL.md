# HTML / SCSS

Builds on `code-design`. Library utility classes (scss-solutions) are covered by `scss-solutions`; a UI
framework's own styling rules live in that framework's skill.

## All styling lives in stylesheets

Never set a style outside SCSS: no `style="..."` attribute and no `element.style.x = ...` from script. (Complete
HTML documents such as email templates are the exception: mail clients need inline styles.) State-driven styling
is a class toggled on the element, with its effect defined in SCSS.

A layout value that depends on a bounded runtime number (a column, a row, a span) becomes classes generated by an
SCSS `@for` from the same variables that define the dimension; the markup applies the class for the value:

```scss
@for $column from 1 through $days {
    .day-column-#{$column} { left: ($column - 1) * $day-width; }
}
```

```html
<div class="entry-cell day-column-3"></div>
```

## No wrapper elements

- Don't add an element just to carry one layout class: put the class on an element that already exists.
- A grouping element is fine when it groups several siblings that have no semantic parent (label, input, error).

## Class names

- No `wrapper` suffix: `container` when the height follows the content, `placeholder` when the height is fixed in
  CSS.
- A class says what the element *is* (`field-container`), never how it looks. A state is a plain adjective class
  (`selected`, `dragging`).
- Write every class name in full in the stylesheet: never build one with `&-title` / `&__title`, so a search for
  the class finds its rule.

## Selectors

- Global element defaults live only in the `elements/` partials and use tag selectors only (`button { }`).
- Everywhere else: class selectors only. No bare tags, no tag + class (`input.form-field`). If an element has no
  class, add one.
- Nesting at most 3 levels deep (aim for 2). No `>`, `+`, `~` or `*` combinators: give the element a class.
- No `!important`. `@extend` only onto a `%placeholder`, never onto a class.
- Don't repeat what a global element style already sets; override only what differs.

## Vendor styles

- Use the library's theming or configuration API before overriding its styles.
- Global overrides of a vendor's styles live in one overrides partial that repeats the vendor's selectors in the
  vendor's order.

## Layout

- **Mobile-first.** Base styles target the smallest screen; larger screens are added with the project's
  `min-width` breakpoint mixins (`@include breakpoints.apply-from-tablet()`). Never a `max-width` query, never a
  bare width `@media`. Prefer intrinsic sizing (`clamp()`, `min()`, `max()`, `flex-wrap`) to a breakpoint where it
  works. Feature queries such as `@media (forced-colors: active)` stay plain.
- **No `display: grid`.** Rows and columns are flex; page columns come from the layout utilities; a 2D surface is
  nested flex containers with absolutely positioned children placed by `@for`-generated classes.
- **No viewport units** (`vh`, `vw`, `vmin`, `vmax`, `dvh`, ...): iOS Safari's dynamic toolbar resizes the
  viewport. Use `%`; for a modal `<dialog>` or overlay `%` resolves against the viewport, so `max-width: 50%` /
  `max-height: 80%` behave like `vw` / `vh` without the bug.
- Custom elements are `display: inline` by default; give one `display: block` (or `flex`) for sizing and
  `overflow` to apply.

## Values

- Colours, spacing, radius, z-index and font sizes come from the design variables, never literals.
- Zero lengths are unitless (`0`, not `0px`); times keep their unit (`0s`).
- Colours in modern syntax (`rgb(0 0 0 / 50%)`), no named colours; numeric `font-weight` (`600`, not `bold`).
- No hand-written vendor prefixes: the build adds them.
- Transitions and animations are switched off or reduced under `prefers-reduced-motion: reduce`.

## DRY SCSS

- Check every literal against the variables in scope. A value correlated with an existing variable (same radius,
  same gap, derived from it) uses or derives from the variable so both move together; a value repeated with no
  variable gets a named one.
- A repeated group of declarations becomes a `%placeholder` (same file) or a mixin (shared).
- A style shared by several pages or widgets (dialog actions, line buttons) is defined once in a global partial,
  never re-declared locally.

## Modules

- `@use` / `@forward` only, never `@import`. Paths leave out the leading `_` and the extension.
- `@use` with the module's natural name (`@use 'variables'` → `variables.$accent`). An alias is allowed only when
  it is a full word naming the module's role (`@use './calendar-grid-variables' as grid`), and the same alias is
  used everywhere that module is imported. Never `as v`, never `as *`.
- A mixin or function private to its file is prefixed with `-` (`@mixin -slot-border`).
