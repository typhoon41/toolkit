# HTML / SCSS

Builds on `code-design`. Library utility classes (scss-solutions) are covered by `scss-solutions`.

## All styling lives in stylesheets

Never set a style outside SCSS: no `style="..."` attribute, no `[style.x]` / `[style.--custom]` binding, no
`element.style.x = ...` from TypeScript. (Complete HTML documents such as email templates are the
exception: mail clients need inline styles.) State-driven styling is a class toggle (`[class.dragging]="isDragging()"`)
whose effect is defined in SCSS.

A layout value that depends on a bounded runtime number (a column, a row, a span) becomes classes generated by an
SCSS `@for` from the same variables that define the dimension; the template binds the class name:

```scss
@for $column from 1 through $days {
    .day-column-#{$column} { left: ($column - 1) * $day-width; }
}
```

```html
<div [class]="entryClasses()" [class.selected]="isSelected()"></div>
```

## No wrappers - use the host element

- Don't add an element just to carry one layout class. Give the component host a class in the decorator,
  `host: { class: 'calendar-grid-container' }`, and remove the wrapper from the parent template.
- Style a host class in the stylesheet of the **component whose template renders it**: the host carries that
  parent's encapsulation attribute, so the rule matches and stays in the parent's lazy bundle. Only a routed page
  (no parent template) is styled in the global partials. Never in the component's own stylesheet, never `:host`.
- Custom elements are `display: inline`; set `display: block` (or `flex`) for sizing and `overflow` to apply.
- A grouping element is fine when it groups several siblings that have no semantic parent (label, input, error).

## Class names

- No `wrapper` suffix: `container` when the height follows the content, `placeholder` when the height is fixed in
  CSS.
- A class says what the element *is* (`field-container`), never how it looks.

## Selectors

- Global element defaults live only in the `elements/` partials and use tag selectors only (`button { }`).
- Everywhere else: class selectors only. No bare tags, no tag + class (`input.form-field`), no `:host`. If an
  element has no class, add one.
- Don't repeat what a global element style already sets (for example a button's font, letter spacing or cursor);
  override only what differs.

## Layout

- **No `display: grid`.** Rows and columns are flex; page columns come from the layout utilities; a 2D surface is
  nested flex containers with absolutely positioned children placed by `@for`-generated classes.
- **No viewport units** (`vh`, `vw`, `vmin`, `vmax`, `dvh`, ...): iOS Safari's dynamic toolbar resizes the
  viewport. Use `%`; for a modal `<dialog>` or overlay `%` resolves against the viewport, so `max-width: 50%` /
  `max-height: 80%` behave like `vw` / `vh` without the bug.
- **No bare width `@media`.** Use the project's breakpoint mixins (`@include breakpoints.apply-from-tablet()`).
  Feature queries such as `@media (forced-colors: active)` stay plain.

## DRY SCSS

- Check every literal against the variables in scope. A value correlated with an existing variable (same radius,
  same gap, derived from it) uses or derives from the variable so both move together; a value repeated with no
  variable gets a named one.
- Colours and spacing always come from the design variables, never literals.
- A repeated group of declarations becomes a `%placeholder` (same file) or a mixin (shared).
- A style shared by several components (dialog actions, line buttons) is defined once in a global partial, never
  re-declared per component.

## Modules

- `@use` with the module's natural name (`@use 'variables'` → `variables.$accent`). An alias is allowed only when
  it is a full word naming the module's role (`@use './calendar-grid-variables' as grid`), and the same alias is
  used everywhere that module is imported. Never `as v`.
