# HTML / SCSS

Library utility classes: `scss-solutions`.

## All styling lives in stylesheets

No `style="..."` attribute and no `element.style.x = ...` (complete HTML documents such as email templates excepted:
mail clients need inline styles). State-driven styling is a toggled class. A layout value from a bounded runtime
number (a column, a row, a span) becomes classes generated by `@for` from the variables that define the dimension:

```scss
@for $column from 1 through $days {
    .day-column-#{$column} { left: ($column - 1) * $day-width; }
}
```

```html
<div class="entry-cell day-column-3"></div>
```

## No wrapper elements

Never add an element just to carry a layout class: use one that exists. Grouping several siblings with no semantic
parent (label, input, error) is fine.

## Class names

- No `wrapper`: `container` when the height follows the content, `placeholder` when it is fixed in CSS.
- Name what the element *is* (`field-container`), never how it looks; states are plain adjectives (`selected`).
- Write class names in full in the stylesheet - never `&-title` / `&__title` - so a search finds the rule.

## Selectors

- Tag selectors only in the `elements/` partials (global defaults). Everywhere else class selectors only: no bare
  tags, no tag + class (`input.form-field`); add a class if missing.
- Nest at most 3 levels (aim for 2); no `>`, `+`, `~` or `*` combinators.
- No `!important`; `@extend` only onto a `%placeholder`.
- Don't repeat what a global element style already sets.

## Vendor styles

Use the library's theming or configuration API first. Global overrides live in one overrides partial repeating the
vendor's selectors in the vendor's order.

## Layout

- **Mobile-first**: base styles for the smallest screen, larger ones through the project's `min-width` breakpoint
  mixins - never a `max-width` or bare width `@media`. Prefer intrinsic sizing (`clamp()`, `min()`, `max()`,
  `flex-wrap`) where it works. Feature queries (`@media (forced-colors: active)`) stay plain.
- **No `display: grid`**: rows and columns are flex, page columns come from the layout utilities, a 2D surface is
  nested flex with absolutely positioned children placed by `@for`-generated classes.
- **No viewport units** (`vh`, `vw`, `vmin`, `vmax`, `dvh`, ...; iOS Safari's toolbar resizes the viewport): use `%`.
  For a modal `<dialog>` or overlay `%` resolves against the viewport (`max-width: 50%`, `max-height: 80%`).
- Custom elements default to `display: inline`: set `block` or `flex` for sizing and `overflow` to apply.

## Values

- Colours, spacing, radius, z-index and font sizes come from design variables, never literals.
- Unitless zero (`0`, not `0px`); times keep their unit (`0s`).
- Modern colour syntax (`rgb(0 0 0 / 50%)`), no named colours; numeric `font-weight` (`600`).
- No hand-written vendor prefixes.
- Transitions and animations are off or reduced under `prefers-reduced-motion: reduce`.

## DRY SCSS

- A literal correlated with an existing variable (same radius, same gap) uses or derives from it; a repeated literal
  with no variable gets a named one.
- Repeated declarations become a `%placeholder` (same file) or a mixin (shared).
- A style shared by several pages or widgets (dialog actions, line buttons) is defined once in a global partial.

## Modules

- `@use` / `@forward`, never `@import`; paths without the leading `_` or the extension.
- `@use` by the natural name (`variables.$accent`). An alias only as a full word naming the module's role
  (`@use './calendar-grid-variables' as grid`), the same everywhere; never `as v`, never `as *`.
- A file-private mixin or function starts with `-` (`@mixin -slot-border`).
